# Vibe Coding Playbook (condensed)

> The unified guide. For long-form depth, see the linked sub-docs.
> Generated by synthesizing 4+ research reports into one opinionated playbook.

---

## 1. Mental model

```
DISCOVERY (JTBD / Story Map)        "what job, for whom, why now"
  ↓
SPEC  (the source of truth)         docs/SPEC.md, requirements/<feature>/spec.md, ADR
  ↓
ENVIRONMENT (the substrate)         README, AGENTS.md, .claude/rules/, docs/gotchas.md, HANDOFF.md
  ↓
MEMORY (4 layers, persistent)       project, user, session, cross-session (handoff)
  ↓
PROMPT CHAIN (per task)             anchor → scaffold → data → logic → route → ui → wire → verify
  ↓
VIBE LOOP (8 steps)                 pre-flight → sketch → spec → scaffold → tests → wire → verify → ship
  ↓
HARDENING                           tests (mutation/property) + NFRs + a11y + SAST + secrets + audit
  ↓
LEARN                               every mistake → AGENTS.md / CLAUDE.md / MEMORY.md
```

> **The spec is the only artifact that survives context loss, session boundaries, model swaps, and team turnover.** Code is regenerated from it; everything else is generated around it.

## 2. File environment (per project)

```
project/
├── README.md  AGENTS.md  CLAUDE.md  CHANGELOG.md  HANDOFF.md
├── docs/
│   ├── SPEC.md  ARCHITECTURE.md  gotchas.md
│   ├── requirements/<feature>/{spec.md, plan.md}
│   ├── decisions/{template.md, NNNN-*.md}
│   ├── handoffs/YYYY-MM-DD-<slug>.md
│   └── runbooks/
├── sessions/  prompts/
└── .claude/{settings.json, rules/<topic>.md, commands/<slash>.md}
```

Use `kit/bin/vibe-init` to scaffold any project.

## 3. Spec-first workflow (the headline)

| Stage | Inputs | Outputs | Tools |
|---|---|---|---|
| **Spec producer** *(Planner OR Coder)* | Goals, users, constraints | Specs, plans, ADRs, prompts, edge cases | Claude.ai, ChatGPT, Gemini, any long-context AI chat — **or** the Coder itself (when no Spec exists) |
| **Coder** | Approved Spec + repo + runnable env | Code, tests, handoffs | Claude Code, Cursor, Antigravity, Aider, Codex, Windsurf |

The Spec is the contract. Either role can produce it; the Coder consumes it.
Planner is **optional**, not required. The Coder-as-discoverer path runs
the spec-first gate at task start: no Spec, no code (unless trivial).

## 4. Requirements gathering (most important)

```
DISCOVERY       SPEC              BREAKDOWN         IMPLEMENT        VERIFY         HARDEN
   └─→ spec.md (AC + edge cases + NFRs + AI surface + risks)
        └─→ plan.md (phases: schema/api/ui/tests/docs)
              └─→ code (per phase, small enough for one Coder session)
                    └─→ verify (mutation-tolerated)
                          └─→ harden (NFRs, a11y, SAST, secrets, audit)
```

See `requirements-gathering.md` for the full canonical pipeline, the Definition of Ready, the Definition of Done, the AI-authored surface area declaration, and the worked example.

## 5. Memory (4 layers)

| Layer | Scope | Lifetime | Authority |
|---|---|---|---|
| Project (`AGENTS.md`, `docs/`) | Repo | Repo history | Team consensus |
| User (`~/.claude/CLAUDE.md`) | Personal | Until edited | You |
| Session (transcript) | Current | Ephemeral | Agent |
| Cross-session (`HANDOFF.md`, handoffs/, auto-memory topic files) | Per-repo | Persistent | Agent + you |

**Boris Cherny pattern**: every mistake that recurs → a rule. Where the rule lives depends on scope:
- Repo-wide → `AGENTS.md` (or `.claude/rules/<topic>.md` with `paths:` if path-specific)
- Personal recurring → `~/.claude/CLAUDE.md`
- Project-private fact → auto-memory topic file

## 6. Prompt chain (per task)

```
Anchor → Scaffold → Data → Logic → Route → UI → Wire → Self-verify
```

- **Anchor**: confirm context (AGENTS.md + spec + plan + handoff)
- **Scaffold**: folder structure, schema migrations (without applying)
- **Data**: models, indexes
- **Logic**: domain logic, each AC = one unit test
- **Route**: HTTP handlers, validation, error envelope
- **UI**: components with loading/empty/error states
- **Wire**: API connection, optimistic where safe, telemetry
- **Self-verify**: run ACs against the result

See `prompts/` for the planner-side prompts.

## 7. Vibe loop (8 steps)

```
[1] Pre-flight → [2] Sketch → [3] Spec → [4] Scaffold → [5] Tests → [6] Wire → [7] Verify → [8] Ship
```

### Verification ranks

| Rank | Check | When |
|---|---|---|
| 0 | Manual smoke | Trivial |
| 1 | Lint + typecheck | Every edit |
| 2 | Unit vs ACs | Every feature |
| 3 | Integration / contract | Every API |
| 4 | Mutation testing | Production |
| 5 | E2E | Customer-facing |
| 6 | Perf / load | Production |
| 7 | Security / pen-test | Regulated |

### Scaling floors

| Stage | Floor | Reviews | Spec depth |
|---|---|---|---|
| Toy | Manual | None | One screen |
| Prototype | Lint + unit | Self | Stub |
| MVP | + integration | 1 human | Full spec |
| Production | + mutation + NFR + a11y + SAST | 1 human + 1 domain | Full spec + ADRs + risk register |
| Regulated | + contract + perf + pen-test | 2 humans + security | Full + compliance + runbooks |

### Kill list (don't ship without)

- [ ] Every AC has a green test
- [ ] Edge cases enumerated and tested
- [ ] NFRs checked
- [ ] Lint + typecheck green
- [ ] No `any` / lint-disable without justification
- [ ] No new dep without approval and registry check
- [ ] No secrets in code or logs
- [ ] CHANGELOG and ADR updated if appropriate
- [ ] Handoff doc written if cross-session
- [ ] Schema migrations reversible
- [ ] Feature flag in place for any AI user-visible change
- [ ] Runbook for any new operational concern

## 8. Missing workflows (the 4 highest-ROI gaps)

1. **Slopsquatting prevention** — verify every new dependency on the registry; quarantine high-risk in a sandbox.
2. **Mutation testing** — without it, "tests pass" is theater.
3. **Feature flags + canary + rollback** — high-variance AI output needs a killswitch.
4. **Per-feature cost tracking with caps** — runaway retries are the most common AI cost spike.

See `gap-analysis.md` for the full comparison.

## 9. First-day checklist

The minimum viable environment that gets you 80% of the value:

- `README.md`, `AGENTS.md`/`CLAUDE.md`, `CHANGELOG.md`, `HANDOFF.md`
- `docs/SPEC.md`, `docs/ARCHITECTURE.md`, `docs/gotchas.md`
- `docs/requirements/README.md`, `docs/decisions/{README.md,template.md}`
- `docs/handoffs/README.md`
- `.claude/settings.json` (PostToolUse format + Stop handoff)
- `.github/PULL_REQUEST_TEMPLATE.md`
- `.gitignore` with `.env*`, `CLAUDE.local.md`
- CI: lint + typecheck + tests on every PR

90 minutes of setup.
