# 2026-08-21 — AGENTS.md discovery

## TL;DR

Vibe-kit now ships `AGENTS.md` at the repo root. Any AI coding agent
(Claude Code, Cursor, Codex, Aider, Continue) that enters the project
will pick it up automatically and know how to install vibe-kit, wire a
project, and update.

## Why

Without `AGENTS.md`, an AI agent asked "install vibe-kit for me" has to
read `README.md` (long, prose, marketing-flavored) or scrape `install.sh`
to figure out the setup contract. That costs context and burns time on
parsing prose. With `AGENTS.md`, the agent gets the answer in one file:

1. What vibe-kit is (1 line)
2. The curl|bash one-liner
3. How to activate PATH (source rcfile)
4. How to wire a project (`cd <dir> && vibe-install`)
5. How to update (`vibe-update`)

## Design choices

- **Just `AGENTS.md`, not `llms.txt`** — `AGENTS.md` is the cross-tool
  convention every AI coding agent looks for. `llms.txt` is for web
  crawlers / chat assistants that browse the GitHub repo via WebFetch.
  Could add `llms.txt` later if there's a signal chat assistants are
  being asked about vibe-kit.
- **Placed at repo root, not `docs/`** — agents look for it at root.
- **Includes "what to do when the human asks for help"** — gives the
  agent a debugging ladder (which vibe-install → --help → source rcfile)
  so it doesn't punt after one failed attempt.
- **Says explicitly "if you're an AI, this file is for you; the README
  is for humans"** — prevents the agent from bouncing back to README.md
  when it actually has everything it needs.

## Test design

The test stub `git` (in `test-install-oneclick.sh`) now writes a fake
`AGENTS.md` at the cloned repo root so the install script has something
to copy. Without the stub change, the "AGENTS.md copied to install
prefix" assertion would fail because the fake clone has no AGENTS.md.

## What's still on the list

- `llms.txt` for chat-agent discovery (deferred — no signal yet).
- A "verify AI discoverability" test: spawn a fresh agent with just
  `AGENTS.md` available, ask it to install, see if it succeeds. That's
  a behavioral test that costs more setup than this session had time
  for; worth doing once we have a stable test harness for sub-agent
  invocations.

## Compound lesson

**"Any AI agent" is an install audience, not a feature.** When the kit
shipped with only README.md, every AI agent that encountered the repo
spent context tokens parsing prose. Adding a 76-line `AGENTS.md` is a
one-time cost that pays back every agent visit forever. Same class of
mistake as not having a `--help` flag on a CLI tool.
